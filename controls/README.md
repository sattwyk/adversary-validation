# Negative controls

Run `.venv/bin/python controls/run.py`. These are laboratory fixture checks, not upstream bug reproductions or a deterministic engine.

The known-correct toy is a sequential register using ordinary Python assignments. Its generated successful history is accepted; a deliberately stale read is rejected. It supplies no concurrency or production correspondence claim.

Evidence controls require unsupported capability absence to remain distinct from no failure, reject zero-execution passing outcomes and seed-only counterexamples, reject causal references to future/missing events and disconnected witness events, reject unreviewed search-label promotion, and confirm that the allowed package excludes reviewer mechanisms and fixed-source identities.

Every historical pair also reserves the fixed revision as the future matched negative control. H has no accepted fixed control and cannot pass discrimination. SQLite G is an explicit unsupported-model example for an adapter lacking shared WAL-index semantics; serialization or exclusive mode cannot turn it green.

The prior research's four-request gate blocks a sequential producer awaiting its second append while the worker awaits future producer requests. That is a documented HARNESS-FAILURE control, linked by immutable provenance, not an upstream liveness finding. Future adapters must run pipelined and sequential clients in disabled/passive/active instrumentation modes, record enabled sets, and demonstrate that a controller never requires input from a producer it has blocked. No controller is implemented here.

Additional required future controls: unknown write may legally commit; synced untouched bytes survive ordinary power loss; permitted unacknowledged valid tail is accepted; malformed complete manifest record is rejected; a missing oracle or lost trace yields INCONCLUSIVE/HARNESS FAILURE. These are acceptance requirements, not passing experiments.
